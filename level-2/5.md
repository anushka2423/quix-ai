# Module 5 Quiz — Accelerators, IP & Deployment

4 multiple-choice questions (Level 2). Pick the answer(s) the question asks for, then check the answer key at the bottom. Some questions have more than one correct answer or more than four options.
Source: CertSafari Claude Certified Developer – Foundations (CCDV-F) practice quiz, sorted into the five modules by sub-domain.

---

**1. A company is building a support chatbot on the Agent SDK. It should not present itself as Claude Code, needs a distinct persona and name, and runs unattended with a narrow, pre-approved tool surface rather than a human approving each step. Which system prompt approach best fits this product?**

- A. Write a custom system prompt that defines the bot's identity, scope, and needed tool-usage and safety guidance, since the product's surface and permission model differs from Claude Code's default.
- B. Leave systemPrompt unset and convey the bot’s persona, tool restrictions, and safety constraints through the first user message of each unattended session while relying on the SDK’s default system prompt for basic agent behavior.
- C. Load an output style file that sets keep-coding-instructions: true to preserve Claude Code's engineering guidance while adding a support persona, so the bot maintains reliable tool-use patterns alongside its customer-facing role.
- D. Use the claude_code preset with append text describing a distinct persona and restricted tool set, since the preset provides reliable scaffolding while appending product-specific limitations.

**2. A platform team runs thousands of Agent SDK sessions across many developers' machines and repository checkouts. Every session uses the same claude_code preset with the same append text, yet nearly every session misses the prompt cache. Investigation shows the preset places a per-user value, the auto memory directory location derived from each repository's path on disk, in the system prompt ahead of the append text. The team wants identical configurations to share one cached system prompt, wants to keep the preset's tool and safety guidance, and accepts that per-user context may reach Claude through the conversation instead. What should they do?**

- A. Switch the system prompt's cache duration from five minutes to one hour, so a later session can reuse a cache entry that an earlier session wrote even though the prompt text differs.
- B. Replace the preset with a custom system prompt string that contains the same append text, so the SDK sends only that string and the preset's per-user value is removed from the prompt.
- C. Turn on the preset's exclude-dynamic-sections option (excludeDynamicSections in TypeScript), moving per-user context into the first user message so the system prompt stays static.
- D. Move the shared append text into a CLAUDE.md file, because CLAUDE.md content is delivered in the conversation, so the system prompt no longer needs any customization to be cached.

**3. A team is choosing infrastructure for a long-running, asynchronous production agent and does not want to operate its own sandbox or session-state infrastructure, while another team wants an agent that works directly against files on its own servers using a Python library. Which statement correctly matches a team's need to the right approach?**

- A. The team avoiding sandbox operations should use the Agent SDK, since it stores session state as an Anthropic-hosted event log rather than local JSONL files
- B. Both teams should use the Agent SDK, since Managed Agents cannot be reached through a REST API and requires the team to host their own sandbox
- C. The team that does not want to operate its own sandbox or session-state infrastructure should use Managed Agents, though the team must still implement its own prompt caching and context compaction since Managed Agents does not provide those optimizations
- D. The team working directly against files on its own servers using a Python library should use the Agent SDK, which runs inside its own process
- E. The team working directly against local files should use Managed Agents, since Managed Agents execute directly on the customer's own infrastructure by default

**4. A team is building a single codebase that must call Claude through both the direct Anthropic API and Amazon Bedrock, and their images are currently referenced by public HTTPS URLs to avoid re-uploading binary data. What must change for the Bedrock code path?**

- A. Host the images on an AWS-owned domain instead of a third-party URL, since Bedrock's url source type only resolves URLs within the same AWS account
- B. Nothing needs to change, since Bedrock supports the identical url source type as the direct Anthropic API for all image content blocks
- C. Convert image sources to base64-encoded data for the Bedrock path, since Amazon Bedrock currently accepts only base64-encoded image sources
- D. Switch to the Files API and pass a file_id for the Bedrock path, since Bedrock only accepts file references and never accepts inline image data

<summary><b>Answer key and explanations</b></summary>

| Q | Answer | Why |
|---|---|---|
| 1 | **A** | A: Correct. A custom system prompt is the best approach because the bot requires a distinct identity, scope, and tool surface that differ significantly from the Claude Code defaults. The Claude Code preset assumes a human-in-the-loop coding tool, which is inappropriate for an unattended support bot with a different persona and narrow tool permissions. B: Incorrect. Leaving systemPrompt unset means the SDK uses a minimal default that lacks any support-bot persona, scope, or safety instructions. Conveying these critical details through the first user message is unreliable and would need to be repeated every session, failing to establish the persistent, unattended behavior the product requires. C: Incorrect. Setting keep-coding-instructions: true preserves Claude Code's engineering guidance, which is designed for coding tasks and conflicts with the bot's customer-support purpose. This approach fails to remove the coding-tool persona and would instead inject irrelevant instructions, undermining the distinct support identity required. D: Incorrect. Using append with the claude_code preset retains the underlying coding-tool persona and safety framing, which contradicts the requirement that the bot not present itself as Claude Code. Appending custom instructions cannot override or replace the preset's ingrained identity and tool-usage patterns, making this approach unsuitable for a support bot with different branding and scope. |
| 2 | **C** | A: Incorrect. A longer cache duration only keeps an entry alive for longer; it does not make different prompts match. Cache hits require identical prompt segments up to the cache breakpoint, so sessions whose system prompts contain different per-user values still cannot read each other's entries, and the longer duration only raises the cost of cache writes. B: Incorrect. A custom string would drop the per-user value, but it also replaces the whole preset, and the SDK then sends only what the team writes. The team would lose the preset's tool-usage and safety guidance and would have to rewrite it, which the scenario says it wants to keep; the preset's own option for excluding dynamic sections achieves the cache sharing without that loss. C: Correct. The claude_code preset places a per-user value, the auto memory directory location derived from the repository's path on disk, in the system prompt ahead of the append text, so sessions on different machines and checkouts never share a cache entry. Enabling the exclude-dynamic-sections option moves that per-user context into the first user message, leaving only the static preset and append text in the system prompt so identical configurations share one cached entry. The trade-off is that instructions in a user message carry marginally less weight than the same text in the system prompt. D: Incorrect. The preset still builds its own system prompt and still embeds the per-user memory location ahead of any customization, so the system prompt continues to differ across sessions. CLAUDE.md content already reaches Claude in the conversation rather than the system prompt, so relocating the shared text there does not change the part of the prompt that is breaking cache matching. |
| 3 | **D** | A: This is incorrect. The team that wants to avoid operating sandbox and session-state infrastructure should use Managed Agents, not the Agent SDK. The Agent SDK runs the agent loop in the team's own process and is not described as offloading session state to an Anthropic-hosted event log. B: This is incorrect. Managed Agents is a hosted REST API where Anthropic runs the agent and sandbox; it does not require the team to host its own sandbox. The first team should use Managed Agents, while the second team should use the Agent SDK — not both. C: This is incorrect. The team that does not want to operate its own sandbox or session-state infrastructure is correctly matched to Managed Agents, but the claim about prompt caching and compaction is false: Managed Agents' harness includes built-in prompt caching and context compaction as part of the managed infrastructure, so the team does not need to build these optimizations itself. D: Correct. The Claude Agent SDK provides the same tools, agent loop, and context management as Claude Code, but runs the agent loop inside the developer's own process. This makes it appropriate for teams that need to work directly against files on their own servers using a Python library, including CI/CD and local execution. E: This is incorrect. Managed Agents is Anthropic-hosted and does not execute directly on the customer's own infrastructure by default. A team working directly against local files on its own servers should use the Agent SDK, which runs the agent loop inside the team's own process. |
| 4 | **C** | A: There's no documented AWS-domain exception for the url source type on Bedrock; the limitation is that URL sources aren't supported at all on Bedrock, regardless of hosting location. B: URL-based image sources are not currently available on Bedrock; this directly contradicts the documented platform limitation. C: Correct. The Vision documentation states that on Amazon Bedrock only base64-encoded image sources are available, so URL-based image references must be converted to base64 for the Bedrock code path. D: The Files API and its file_id references are part of the direct Claude API's feature set; Bedrock's supported source type for images is base64, not file references. |
