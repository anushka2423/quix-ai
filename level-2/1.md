# Module 1 Quiz — MSO Foundations

16 multiple-choice questions (Level 2). Pick the answer(s) the question asks for, then check the answer key at the bottom. Some questions have more than one correct answer or more than four options.
Source: CertSafari Claude Certified Developer – Foundations (CCDV-F) practice quiz, sorted into the five modules by sub-domain.

**1. A team using Claude Sonnet 5 wants to guarantee the lowest possible latency on simple lookup queries by turning reasoning off completely for those requests. Simply omitting the thinking configuration does not achieve this. What should they do instead?**

- A. Set thinking type to enabled with an explicit budget_tokens value
- B. Omit the thinking parameter entirely from every request
- C. Set effort to low while leaving the thinking parameter untouched
- D. Set thinking type to disabled explicitly in the request

**2. During a multi-turn agentic workflow, Claude produces a thinking block followed by a tool_use block, and the application executes the tool and needs to continue the conversation. Which approach correctly preserves the interleaved thinking behavior on the next turn?**

- A. Move the original thinking block from the assistant turn to a position immediately after the tool_result in the subsequent user turn, structuring the sequence as tool_result, then thinking, then the new user message.
- B. Include the original thinking block and the tool_use block unchanged in the assistant turn, then supply the tool_result in the next user turn without altering the thinking block's text or order.
- C. Summarize the thinking block's key reasoning steps and tool call intent into a concise summary, then include this summary instead of the original thinking block in the next user turn preceding the tool_result.
- D. Drop the thinking block from the assistant turn after the tool executes, then construct the next user turn as a message containing the tool_result and the original tool_use block, omitting the thinking block entirely.

**3. A team is documenting the ground rules for extended thinking before rolling it out across their agentic tool-calling pipeline. Select the statements below that accurately describe extended thinking mechanics. (Select 3.)**

- A. Toggling thinking on and off mid-turn causes thinking to be silently and gracefully disabled for that turn rather than raising a hard validation error
- B. budget_tokens must be set to a value strictly less than max_tokens, since the thinking budget has to fit within the overall output token ceiling
- C. Thinking blocks must be passed back to the API unmodified, since their sequence and content cannot be rearranged or edited across turns
- D. Changing the thinking budget between requests invalidates the cached system prompt in addition to invalidating the cached message history
- E. Setting display: "omitted" still streams the full thinking_delta events so developers can inspect Claude's reasoning while suppressing it from end users

**4. A chat agent resends the same tool definitions, system prompt and full conversation history on every request, using one top-level automatic cache_control breakpoint. Earlier turns contain user-uploaded screenshots, and requests arrive seconds apart. After a client release, the app re-compresses every stored screenshot before resending it, so the image bytes differ slightly from the previous request even though the pictures look identical. Since then the conversation history is rewritten to the cache on every request instead of being read. Why does this happen?**

- A. The cache compares what an image shows rather than its bytes, so the misses come from expiry; the team should set a ttl of one hour on the image blocks.
- B. The lookback window checks only the twenty most recent blocks, so a long conversation with images always falls outside it and has to be rebuilt each turn.
- C. A hit needs the prefix to match exactly, image bytes included, so re-encoded screenshots change it and the earlier turns miss the cache.
- D. Images cannot be part of a cached prefix, so any conversation that contains a screenshot is processed without the cache and rewritten on every request.

**5. An engineering team is deciding between the realtime Messages API and the Message Batches API for several workloads. Select the workloads that are well suited to the Message Batches API. (Select 2.)**

- A. Powering an IDE assistant for 3,000 developers, where replies must render incrementally the moment Claude begins generating.
- B. Driving an agent loop that runs a tool locally after each response and sends the tool_result straight back to continue the same task.
- C. Running a 20,000-case prompt regression suite overnight, where each case is an independent request reviewed the next morning.
- D. Re-scoring 200,000 archived support documents with a new rubric, where results are only needed sometime within the next day.
- E. Screening 50,000 checkout payments an hour for fraud, where each decision must reach the shopper within about two seconds.

**6. A developer configures thinking={"type": "enabled", "budget_tokens": 32000} alongside max_tokens=16000 and the request fails validation. What is the correct fix?**

- A. Remove max_tokens entirely, since extended thinking requests calculate the output ceiling automatically from the thinking budget
- B. Increase max_tokens to exactly double budget_tokens, which is the fixed ratio the API enforces between thinking and final output tokens
- C. Lower budget_tokens to a value strictly less than max_tokens, since the thinking budget must fit within the overall output token ceiling
- D. Switch budget_tokens to a negative offset from max_tokens so the API can compute the remaining space for the final text response

**7. A team runs a code-review agent at the default effort level and is satisfied with its quality. A manager proposes setting the effort level to max on every request "so the agent is always at its best." What is the soundest response?**

- A. Set max but lower max_tokens to cap spend, since max_tokens is what limits how much the model reasons and acts
- B. Raise every request to xhigh instead, since it captures most of the gain of max at a lower cost
- C. Keep the default, and step up only for the hardest tasks where an eval shows a gain, treating max as a ceiling test
- D. Use max only on turns that call tools and low on text-only turns, since effort applies to tool calls but not to text
- E. Replace effort with a fixed thinking token budget, since effort is not meant for agentic coding workloads
- F. Agree, because max removes every token constraint and so can only improve results, and cost is a secondary concern

**8. Which of the following statements correctly describe how adaptive thinking behaves? (Select all that apply)**

**9. A research tool fans out 25 parallel Claude API requests at the same instant, each beginning with an identical 30,000-token cached document prefix marked with cache_control. The cache was cold before the fan-out. Which change best fixes this cost problem?**

- A. Raise max_tokens on each request, so the response runs long enough for the cache write to finish before the other concurrent requests are processed by the API

- C. Send one request carrying the shared prefix first and wait until its response begins, then launch the other 24 requests, so they read the entry that request wrote
- D. Add a second cache_control breakpoint at the end of the shared prefix on each request, so the lookback window can find entries written by sibling requests at that moment

**12. A multi-turn chatbot appends each new user and assistant turn to the conversation and calls the Messages API with a single automatic cache_control breakpoint at the request level. During a long session, a user attaches an image partway through the conversation, then continues asking text-only questions for many more turns. After the image is added, the team notices cache_read_input_tokens drops sharply for the next request but recovers on subsequent ones. What best explains this behavior?**

- A. Cache reads dropped because the 20-block lookback window was permanently exceeded after the image was added, and the cache cannot recover unless a new explicit breakpoint is placed after the image; the subsequent recovery indicates that the breakpoint was automatically shifted.
- B. The automatic cache_control breakpoint silently disables itself once a non-text content block appears anywhere in the conversation, causing the next request to bypass the cache, but the breakpoint reactivates on later text-only requests, which explains the brief drop in cache reads.
- C. Adding an image to the messages invalidates the cached content only from that point forward, so the turn containing the image is a partial cache miss, and cache rebuilds and hits normally on later turns once the new prefix stabilizes.
- D. Images are never eligible for prompt caching under any circumstances, so after the image is added every turn becomes a full cache miss; the cache recovers because the system later excludes the image from the cached prefix, allowing reads on the text-only portion.
